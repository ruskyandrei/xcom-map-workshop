An early preview: see the README for what you need and the user guide (in the release) for how it works.

**Download** `XCOM-Map-Workshop-0.4.1-Setup.exe` (recommended) or the zip. Windows SmartScreen may say "Windows protected your PC" because the installer isn't signed: choose More info, then Run anyway.

**Upgrading from 0.4.0:** install over it. Your projects and builds are kept, and maps don't need preparing again. Two things change by themselves:
- What earlier plays left in your game (the map records, landing zones and files of builds you played) is taken out the first time the editor opens with XCOM closed. Your builds are untouched, and playing one puts it back in for that play.
- **Remove from game** has moved: it is now **Undo everything** in the new Game maps window (Project menu).

### New features
- **Project manager** (Project menu, **Manage projects…**): every project with its last build (when it was built, of which revision, whether its lighting is baked, and the editor version that built it) and what is in the game of it.
  - Filter by text or by state, sort by any column, and tick projects one by one, as a Shift+click run, or all that the filter shows (Ctrl+A).
- **Install maps for campaigns.** Until now a build could only be played in a test battle. The manager's **Install in the game** puts the ticked projects' builds into the game's map list so that campaign missions use them, one of two ways:
  - **Additional maps**: your map joins the rotation beside the original, and missions draw from both.
  - **Replace the original maps**: your map is used where the original was. The original's records are commented out, not deleted, and come back when you undo it. This also covers council missions, which ask for their map by name.
  - Each row's **Install as** gives that project its own way, so one install can replace some maps and add others.
  - The manager warns, without stopping you, about a build whose lighting isn't baked, a build older than its project, and maps that serve missions other than abductions.
- **Map packs.** **Zip as a map pack** makes one zip of the ticked builds to hand to other players, who don't need the editor:
  - **Install.cmd** asks for their game folder (it offers the Steam install it finds), keeps a copy of `DefaultMaps.ini` as it is, copies the files and adds the maps, replacing or adding as you chose for each.
  - **Uninstall.cmd** takes the pack out again and says whether `DefaultMaps.ini` is exactly as it was.
  - The zip's README also lists every line, to add by hand.
- **Game maps** (Project menu, **Game maps…**): every map record the game has, by map or by mission, saying whether missions draw it from the rotation or ask for it by name, and what the editor did to it.
  - Untick a record of the game's own and the game stops using it; tick it to bring it back. **Switch off the shown** and **Switch on the shown** do it for everything the filter shows.
  - A map replaced by one of your projects says by which. Each record the editor added has **Undo**, which takes that project out and brings back the map it replaced.
  - **Undo everything** takes all of the editor's back out of the game: the config files end exactly as they were.

### Changes
- **Play in game leaves nothing behind.** What a play installs is taken out again once XCOM has closed (or the next time the editor opens, if it was closed meanwhile). Maps installed through the project manager stay. A tactical save made during a test battle on a build won't load afterwards.
- **Remove from game** is gone from the Project menu: Game maps' **Undo everything** does the same, and its **Undo** takes out one project.
- The user guide has a section for the project manager and one for Game maps, and its Project menu picture shows the new items.

### Bugs fixed
- A build stopped with "the hidden piece at … crosses no tile of the map" when a deleted, copied or cover piece stood outside the map's playable tiles, such as the backdrop pieces round Basic Training (a tester's build report: thank you).

### Known limits
- **Maps installed for campaigns haven't been played in a campaign yet.** Installing, replacing and undoing are checked on the game's files, down to the byte, but not yet in the game: whether a campaign draws an added map, stops drawing a replaced one, and plays a replaced council mission's map is still to be confirmed. Only abductions have been played with an edited map. Please report what you see.
- **Council missions can be replaced but not added to.** The game has a fixed list of council missions, each tied to one map by name, so a map installed as *additional* is never picked for one (it still joins the rotation for its other missions). Install it to *replace* the original to play it there. The one exception: Long War turns an extra bomb map into an extra bomb mission, so an additional map on a bomb map should appear as one (not played yet).
- A map pack's lines copy the records of the install it was made from. A game with other records for those maps (another Long War version, plain Enemy Within) gets yours; a map whose base map that game doesn't have is left out. The scripts were tried on Long War Rebalance only.
- Undoing one project in Game maps leaves its files in the game until Undo everything.
- A first-mission install made by a version before 0.3.0 is put back at the next Play in game or by Undo everything, not by the automatic clean-up.
- Tried with Long War Rebalance through Steam. Plain Enemy Within, other Long War versions and game folders outside Steam haven't been tried.
- The test battle is a plain one with six squaddies, not a campaign mission.
- A cover block gives no cover to a soldier standing on a slope (the game's rule), though it still blocks movement there. Ragdolls and debris pass through blocks.
- Pieces moved off the grid build with a warning, but haven't been played in the game yet. A ladder off the grid climbs from the tiles its ends fall in.
